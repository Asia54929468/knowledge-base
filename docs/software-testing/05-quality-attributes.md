# 质量属性与专项测试

<div class="section-lead">功能正确只是质量的一部分，还要验证系统在真实约束、故障和多样环境下的表现。</div>

## 性能与容量测试 { #performance-and-capacity }

性能测试用响应时间、吞吐量、并发量和资源利用率评价系统在不同负载下的行为。有效结论需要真实场景模型、稳定环境和监控数据共同支撑。

### 性能测试

- **响应时间**：从请求发出到收到完整响应所经历的时间，常关注平均值和 P90、P95、P99 等分位数。
- **吞吐量**：单位时间内系统完成的请求数、事务数或数据量。
- **并发用户数**：同一时间与系统交互或保持会话的用户数量。
- **TPS / QPS**：每秒处理的事务数 / 查询数，口径必须在测试前明确。
- **资源利用率**：CPU、内存、磁盘、网络、线程、连接池等资源使用情况。
- **负载测试**：在预期或逐步增加的负载下验证性能目标和容量。
- **压力测试**：超过正常负载，寻找系统极限、失败方式和恢复能力。
- **峰值 / 尖峰测试**：验证负载突然上升或下降时系统的适应能力。
- **稳定性 / 耐久测试**：长时间运行以发现内存泄漏、资源耗尽和性能衰减。
- **容量测试**：确定系统可支持的数据量、用户量或事务量上限。
- **可伸缩性测试**：验证增加或减少资源后，系统性能能否合理变化。
- **基准测试**：在固定条件下建立性能基线，用于版本或方案比较。
- **性能场景**：模型应尽量接近真实业务比例、用户行为、数据量和思考时间。
- **性能瓶颈**：可能出现在客户端、网络、应用、数据库、缓存、消息队列或外部依赖。
- **常见工具**：JMeter、k6、Locust、Gatling 等；监控数据与压测结果需要联合分析。

> 负载测试主要评价系统在预期或逐步增加负载下的表现；压力测试会超过正常负载，用于寻找极限、观察失败方式和验证恢复能力。

## 安全与隐私测试 { #security-and-privacy }

安全测试围绕身份、权限、会话、输入、敏感数据和配置验证防护能力。攻击性测试必须在明确授权和范围内开展，自动扫描结果也需要人工确认。

### 安全测试

- **身份认证**：验证账号身份识别、密码策略、多因素认证、验证码和登录保护。
- **授权控制**：验证用户只能访问被允许的功能和数据，防止水平与垂直越权。
- **会话安全**：验证 Token / Session 的生成、过期、撤销、固定攻击防护和安全存储。
- **输入安全**：关注 SQL 注入、命令注入、XSS、路径遍历和不安全反序列化等问题。
- **敏感数据保护**：检查传输加密、存储加密、脱敏、日志泄露和密钥管理。
- **文件安全**：验证文件类型、大小、内容、扩展名、存储位置和访问权限。
- **业务安全**：验证防刷、防重放、防薅羊毛、交易限额和关键操作二次确认。
- **安全配置**：检查默认账号、调试模式、错误信息、跨域策略、开放端口和依赖版本。
- **审计与追踪**：关键操作应有完整、可靠且受保护的审计日志。
- **漏洞扫描**：使用自动化工具识别常见漏洞，但扫描结果需要人工确认。
- **渗透测试**：在明确授权和范围内模拟攻击者验证系统防护能力。
- **安全测试边界**：不得在未授权的系统、账号或数据上进行攻击性测试。

## 兼容、部署与本地化测试 { #compatibility-deployment-localization }

软件需要适应不同平台、版本、配置、安装升级路径和区域文化。测试组合应依据用户分布、支持范围与失败影响确定优先级。

### 兼容性测试

- **浏览器兼容**：验证不同浏览器、内核和版本下的功能与展示。
- **操作系统兼容**：验证不同桌面或移动操作系统及其版本。
- **设备兼容**：验证不同品牌、型号、分辨率、硬件和外设。
- **版本兼容**：验证客户端与服务端、新旧数据格式、API 版本之间的兼容。
- **前向兼容**：旧系统或旧版本能否处理新版本产生的数据或交互。
- **后向兼容**：新系统或新版本能否继续支持旧版本的数据或客户端。
- **共存性**：验证软件与其他应用同时运行时是否互相影响。
- **配置兼容**：验证不同语言、时区、网络、数据库和中间件配置。
- **兼容矩阵**：根据用户占比、业务风险和官方支持范围确定优先测试组合。

### 安装、升级与配置测试

- **安装测试**：验证全新安装、默认路径、自定义路径、依赖检查和安装失败处理。
- **卸载测试**：验证程序、服务、快捷方式和数据是否按设计移除或保留。
- **升级测试**：验证版本升级、跨版本兼容、数据迁移和配置继承。
- **回滚测试**：升级失败或上线异常时，验证程序、配置和数据能否安全恢复。
- **补丁测试**：验证补丁安装、覆盖范围、依赖、回退和对现有功能的影响。
- **配置测试**：验证默认值、合法 / 非法配置、动态生效、重启生效和配置组合。
- **部署测试**：验证部署脚本、顺序、权限、依赖、健康检查和多节点一致性。
- **重复执行**：安装或部署脚本重复执行时应保持可预测结果，避免产生重复资源。

### 国际化与本地化测试

- **国际化（i18n）**：验证产品架构是否支持多语言、多地区和不同文化规则。
- **本地化（l10n）**：验证产品针对特定语言和地区的翻译与适配质量。
- **文本显示**：检查截断、重叠、换行、占位符、复数和从右到左文字。
- **字符编码**：验证 Unicode、多语言输入、存储、搜索和导入导出。
- **区域格式**：验证日期、时间、时区、数字、货币、单位、地址和电话号码格式。
- **文化适配**：检查图片、颜色、符号、排序和表达是否符合当地习惯。
- **语言切换**：验证运行时切换、默认语言、回退语言和语言持久化。
- **伪本地化**：使用扩展或变形文本提前发现硬编码、布局和字符支持问题。

## 易用性与无障碍测试 { #usability-and-accessibility }

易用性关注用户能否理解并高效完成目标，无障碍关注不同能力用户能否使用核心功能。两者都需要从真实任务和反馈出发，而不只是检查视觉效果。

### 易用性与无障碍测试

> 本节的易用性对应 Usability，关注用户是否容易使用；可靠性中的可用性对应 Availability，关注系统需要服务时是否处于可工作状态。

- **易学性**：新用户是否容易理解并学会使用系统。
- **操作效率**：用户能否用合理步骤快速完成目标。
- **防错性**：系统能否预防误操作，并在出错时提供清晰恢复方式。
- **一致性**：相同元素、术语和操作在不同页面应保持一致。
- **反馈及时性**：加载、提交、成功、失败和进度状态应得到明确反馈。
- **帮助与提示**：说明、占位符、错误信息和帮助内容应准确且有行动指引。
- **键盘可操作性**：核心功能应支持合理的焦点顺序和键盘操作。
- **屏幕阅读器支持**：界面应具有合适的语义、标签和替代文本。
- **视觉可达性**：关注颜色对比度、缩放、字号、闪烁和不能只依赖颜色传达信息。
- **用户测试**：邀请真实或代表性用户执行任务，观察成功率、耗时和困惑点。

## 可靠性、韧性与容灾测试 { #reliability-resilience-recovery }

可靠性测试关注系统持续服务、容忍局部失败和恢复数据与状态的能力。验证对象包括降级、熔断、重试、故障转移、备份恢复和灾难预案。

### 可靠性、恢复与容灾测试

- **成熟性**：系统在正常运行中避免故障的能力。
- **可用性（Availability）**：系统在需要时处于可工作状态的比例。
- **容错性**：部分组件或依赖失败时，系统仍能保持必要服务的能力。
- **可恢复性**：发生故障后恢复服务、状态和数据的能力。
- **故障转移**：主节点失效后能否自动或手动切换到备用节点。
- **降级**：部分功能不可用时保留核心服务，并向用户提供合理反馈。
- **熔断**：依赖持续失败时暂时停止调用，避免故障扩散。
- **重试**：临时故障后再次请求，应控制次数、间隔，并避免重复副作用。
- **备份恢复测试**：验证备份文件不仅存在，而且能够在目标时间内正确恢复。
- **灾难恢复测试**：模拟机房、区域或关键基础设施故障，验证应急预案和恢复流程。
- **RTO**：发生灾难后，业务允许的最长恢复时间。
- **RPO**：发生灾难时，业务允许丢失的最大数据时间范围。
