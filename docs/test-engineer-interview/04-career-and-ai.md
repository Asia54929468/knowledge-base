# 职业认知与人工智能

职业认知类问题需要结合质量目标、团队协作和技术变化说明判断，既体现积极态度，也说明现实边界。

### 参考答案

我认为软件测试的核心是识别质量风险，并为产品是否能够交付提供客观依据，而不仅仅是找出多少个缺陷。测试人员既要按照需求验证功能是否正确，也要站在用户和业务角度判断产品是否真正可用。

测试应该尽早介入。需求和设计阶段发现一个问题，通常比开发完成后再修改成本更低。因此，测试人员需要参与需求评审，提前发现不明确、不可测或存在风险的内容；在测试执行阶段，则通过系统的方法验证功能和相关质量要求，并把问题和风险清楚地反馈给团队。

我也认为质量不是测试团队单独负责的。测试需要与产品、开发共同协作，推动问题得到解决。在时间和资源有限的情况下，测试人员还要根据用户影响和业务风险安排优先级，帮助团队在质量、成本和进度之间作出合理判断。

## 如何看待人工智能？ { #artificial-intelligence-perspective }

### 回答思路

<div class="interview-answer interview-answer--viewpoint" aria-label="对人工智能的观点结构">
  <p class="interview-answer__thesis">人工智能（Artificial Intelligence，AI）能够提高研发与测试效率，但不能替代业务判断和质量责任。</p>
  <ul class="interview-answer__supports interview-answer--3" role="list">
    <li><span class="interview-answer__label">实际价值</span><span class="interview-answer__note">辅助分析、设计、编码和排查</span></li>
    <li><span class="interview-answer__label">使用边界</span><span class="interview-answer__note">校验输出并保护敏感数据</span></li>
    <li><span class="interview-answer__label">能力变化</span><span class="interview-answer__note">强化业务、策略和风险判断</span></li>
  </ul>
</div>

### 参考答案

我认为 AI 首先是一种提高研发效率的工具，可以加快需求分析、编码和产品迭代，但研发效率提高并不代表质量风险减少。AI 生成的代码可能存在逻辑遗漏、隐蔽缺陷、安全和可维护性问题。如果团队缺少对生成内容的理解，产品也会表现得更像“黑盒”。因此，测试不仅要验证功能结果，还需要关注业务逻辑、边界场景、数据安全和整体质量风险。

对测试工程师来说，AI 可以辅助分析需求、补充测试点、生成测试数据和自动化脚本，也能帮助分析日志、定位问题和整理报告，从而提高测试效率和覆盖率。但 AI 可能产生错误，也不了解全部业务背景，其输出仍需人工验证，敏感数据也不能随意输入。未来测试工程师的价值会更多体现在业务理解、测试策略和风险判断上。我会主动使用 AI 提效，但不会直接依赖其结论，最终的质量判断仍由测试人员负责。
