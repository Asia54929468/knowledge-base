# 特色设计与工程化

## 可复用的特色设计

以下设计来自真实接口自动化中的常见难点，不是所有项目的必选项。

### 路径参数检查与 URL 编码

在发送请求前检查 `/users/{id}` 中的占位符是否都有值，并只对参数值编码。

- **收益**：更早发现漏参，正确处理中文、空格和斜杠。
- **风险**：不要重复编码整条 URL；`None` 应报错，不应变成字符串。

### 登录前获取公钥并加密

某些客户端登录流程是：

```text
获取公钥 → 生成临时密钥或随机数 → 按协议加密密码 → 登录
```

- **收益**：自动化行为与真实客户端一致，而不是绕过安全协议。
- **实现建议**：加密算法放在 `common/crypto.py`，登录 API 只负责编排。
- **风险**：必须匹配字符编码、nonce 长度、拼接顺序和输出格式；使用成熟密码库，不自行设计算法。

### 缓存 Token 和公共资源 ID

- **收益**：减少重复登录和前置查询，提高执行速度。
- **风险**：logout、改密、过期和并行执行都会使共享缓存失效；“列表第一条”也不是稳定资源选择方式。
- **改进**：提供 `force_refresh`/`clear`，按环境、账号和 worker 隔离缓存，通过唯一名称选择资源。

### 成功记摘要，失败展开详情

成功请求只记录方法、路径、状态码和耗时；测试失败后再输出本用例全部请求的脱敏详情。

- **收益**：降低日志噪声，又保留失败现场。
- **风险**：只记录最后一个响应会丢失前置过程；正文必须截断，Header、URL 和 JSON 都要脱敏。

### 辅助功能不覆盖原始失败

日志、截图、报告附件和通知失败时，应记录辅助异常，但保留原始测试失败。否则排查者看到的是“报告生成失败”，而不是最初的业务断言失败。

### 状态操作的恢复

修改密码、创建资源、切换开关等操作应使用 `yield fixture` 或 `finally` 恢复状态。同时需要唯一数据和定时垃圾清理作为兜底，因为进程被强制终止时 teardown 也可能无法执行。

### 配置键引用敏感数据

测试 YAML 使用 `username_setting: username`，运行时再从安全配置解析真实值。这样保留数据结构，同时避免把凭据复制到测试数据中。配置键需要校验，日志仍需二次脱敏。

## 安全与工程化

### 凭据与 SSL

- 凭据使用环境变量、CI Secret 或 Secret Manager，不提交 Git。
- 测试账号遵循最小权限，并定期轮换。
- `verify_ssl` 默认开启；自签证书优先配置 CA，不要直接关闭校验。
- Header、URL 查询参数、请求体和响应体都需要脱敏。

### 重试边界 { #retry-boundaries }

只对短暂网络错误以及 429、502、503、504 等情况考虑有限重试，并满足：

- 请求是幂等的，或使用可靠的幂等键。
- 重试次数、退避时间和总耗时有上限。
- 日志能区分首次请求与重试。

“请求没有可靠完成”的网络重试与“请求成功但任务尚未完成”的业务轮询是两种机制。POST、扣费、创建等非幂等操作不能盲目重试。

### 测试金字塔

```text
少量真实环境端到端测试
        ↑
接口契约与集成测试
        ↑
大量配置、HttpClient、数据和脱敏逻辑的 Mock 单元测试
```

真实环境测试最接近用户链路，但速度慢、数据治理成本高；框架自身逻辑应优先通过快速 Mock 测试覆盖。

### 并行执行前置条件

启用 `pytest-xdist` 前确认：

- 每个 worker 使用独立账号或数据命名空间。
- 不共享可变的全局 Session。
- 测试不会操作同一资源。
- 日志和报告文件名包含 worker ID。
- 状态型、破坏性测试单独串行执行。

### 报告与可追溯性

失败结果至少保留：环境名、代码版本、依赖版本、用例 ID、JUnit/HTML/Allure 报告和脱敏日志。报告中不得出现密码、完整 Token、Cookie 或私钥。
